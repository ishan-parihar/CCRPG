# Cognitive / Amber — Social-Cooperative Game Concept

> **Axis:** The social-cooperative axis probes cognitive intelligence through SHARED RULE-FOLLOWING — can the player coordinate cognitive effort with others within a rule-system? At Amber, this is: "The code requires us to work together. Can you follow the rule AND coordinate with your companion? Can you think TOGETHER within the system?"
>
> **Why this axis for Cognitive/Amber:** Amber is the stage of GROUP BELONGING. Cognitive capacity at Amber includes coordinating thought with others — shared classification, collaborative sequencing, group rule-following. This modality tests whether the player can think systematically WITH others, not just alone.

---

## 1. Game Identity

- **Title:** "The Shared Codex"
- **Core mechanic:** Player and companions COORDINATE cognitive effort within a shared rule-system — collaborative classification, sequencing, and divided labour. "The code requires both of you. You classify the reds. Your companion classifies the blues. Together you complete the ledger."
- **Duration:** 3–5 minutes per session (infinite checkpoints; fatigue-aware)
- **Internal progression:** The First Partnership → The Shared Rule → The Divided Labour → The Changing Roles → The Living Order

---

## 2. Catalyst Delivery

**What this modality uniquely presents:** Cognitive tasks that REQUIRE coordination with another mind — shared rule-systems where neither party can complete the work alone. The contact boundary is: "Can you think systematically with others?"

**How it differs from the other 6:** Other modalities test solo cognitive capacity (rule-following, sequencing, classification). This modality tests whether the player can maintain cognitive rigour WHILE coordinating with a companion — shared timing, divided labour, mutual trust in each other's contributions.

**What it uniquely surfaces:** Cognitive domination (enforcing own approach), cognitive isolation (inability to coordinate), cognitive imperialism (taking over all roles), and collaborative rigidity (refusing role-changes). These social-cognitive patterns are invisible in solo tasks.

**Successful integration:** The player can think systematically with others — contributing AND receiving, leading AND following — the social foundation of concrete operational thought.

---

## 3. Game Design

### Setup
The Shared Codex: a collaborative classification/sequencing space. Player and companion each have a role within a shared rule-system. Items flow in; each person classifies/sequences their portion; the shared ledger fills. Aesthetic: Amber-stage scriptorium — two scribes at adjacent desks, shared codex between them.

### Interaction Phases
- **The First Partnership (1–5):** Simple parallel shared task. "You sort left. They sort right. Together the ledger fills."
- **The Shared Rule (5–15):** Same rule, different items. Coordinate timing and accuracy.
- **The Divided Labour (15–30):** Different rules for different roles. "You sort by colour. They sort by shape. Both needed."
- **The Changing Roles (30–50):** Roles swap. Adapt to new position within same system.
- **The Living Order (50+):** Full collaborative integration: shared rules + divided labour + role-flexibility + mutual support.

### Feedback
- Good coordination → "The codex fills. Two minds, one system. Well coordinated."
- Enforcement → "They're doing it correctly — just differently. Both valid."
- Non-coordination → "The codex needs both of you. The system is incomplete without you."
- Takeover → "That's their role. Trust them. Do YOUR part."
- Role-rigidity → "Same system. New seat. You can do this."

### Difficulty Adaptation
- Task complexity: simple shared sorting → divided labour → role-switching
- Coordination demand: independent parallel → interdependent → sequential handoff
- Disagreement: harmonious → companion uses different (valid) approach → companion makes errors
- Role-change frequency: stable → occasional → frequent
- Group size: dyad → triad → small group

### Progression Table
| Phase | Checkpoints | What changes |
|---|---|---|
| The First Partnership | 1–5 | Simple parallel shared task |
| The Shared Rule | 5–15 | Coordinated timing and accuracy |
| The Divided Labour | 15–30 | Different roles, same system |
| The Changing Roles | 30–50 | Role-swapping and adaptation |
| The Living Order | 50+ | Full collaborative cognitive integration |

## 4. Item Pool

| Type | Pool size | Description |
|---|---|---|
| Parallel tasks | 20+ | Same rule, different items (basic coordination) |
| Divided tasks | 15+ | Different rules for different roles (specialisation) |
| Sequential tasks | 15+ | One person's output feeds another's input (handoff) |
| Role-swap tasks | 10+ | Familiar tasks with swapped positions |
| Disagreement tasks | 10+ | Companion uses different valid approach |

---

## 5. Technical Requirements

- **Inputs:** Tap/drag (classify/sequence own items); signal (coordinate with companion); confirm (accept shared result)
- **Timing:** Coordination timing tracked; individual contribution rate; shared completion time
- **NPC/AI:** Companion system (NPC with own cognitive style and valid approaches); shared-task system; coordination tracking (timing, accuracy, role-adherence); dominance detection; role-swap system
- **LLM level:** Low — companion behaviour generation and nuanced collaboration assessment; core coordination metrics algorithmic
- **State persistence:** Coordination history; independence scores; reception quality; role-flexibility metrics; collaborative efficiency; dominance/non-participation/takeover/rigidity indicators; fatigue state; checkpoint position
