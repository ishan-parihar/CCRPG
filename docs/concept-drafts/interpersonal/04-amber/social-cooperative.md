# Interpersonal / Amber — Social-Cooperative Game Concept

> **Axis:** Live group coordination — coordinating with NPC group members through shared code, responding to code-violations by group members, and maintaining group cohesion under pressure.
> **Why this axis for this module:** Group-belonging at Amber is fundamentally ENACTED in live group contexts. This modality presents the actual experience of coordinating through shared code with others who may enforce, desert, perform, or refuse — revealing the player's genuine relational structure.

---

## 1. Game Identity

- **Title:** "The Order in Action"
- **Core mechanic:** The player coordinates with 2-3 NPC group members through a series of shared tasks. Each NPC has a distinct relational style (one enforces rigidly, one tends toward lone-wolf behaviour, one performs sophistication). The player must navigate genuine group coordination while maintaining their own relational health.
- **Duration:** 5-12 minutes per session
- **Internal progression:** The Shared Task → The Code in Action → The Member's Deviation → The Group's Response → The Order Holds

---

## 2. Catalyst Delivery

**What this modality uniquely presents:** The LIVE RELATIONAL dimension of group-belonging — how the player coordinates in real-time with others who have their own relational styles. Unlike all other modalities (which present structured tasks), this modality presents the actual texture of group life.

**How this differs from other modalities:** Unlike deterministic (objective coordination tasks), this modality presents live group dynamics. Unlike scenario-choice (individual decisions), this modality requires ongoing relational navigation. Unlike strategic-planning (planning group coordination), this modality requires executing coordination in real-time with unpredictable group members.

**What it uniquely surfaces:** The enforcer will attempt to control the group. The lone wolf will resist coordination. The premature diplomat will perform sophisticated relating without genuine belonging. The belonging-refuser will coordinate but refuse to examine the group's relational demands.

**Successful integration:** The player coordinates effectively with diverse group members — maintaining their own role, supporting others in theirs, responding appropriately to deviations, and maintaining group cohesion without either enforcing rigidly or abandoning collectively.

---

## 3. Game Design

### Setup
The Order in Action: a live group-coordination interface where the player and 2-3 NPC companions execute shared tasks. Each companion has a distinct relational style that creates coordination challenges. Aesthetic: Amber-stage group action — the guild on a mission, the order in ceremony, the lived texture of collective belonging.

### Interaction
- **The Shared Task (1-5):** Simple group task requiring basic coordination. "The three of you must secure the gate together." Tests basic live group-coordination.
- **The Code in Action (5-15):** More complex coordination requiring role-appropriate behaviour from all members. Tests whether the player can coordinate through the code in real-time.
- **The Member's Deviation (15-30):** One NPC deviates from their role. "Aldric is enforcing instead of coordinating. What do you do?" Tests response to live relational deviation.
- **The Group's Response (30-50):** The group must collectively respond to a challenge that tests their code-coordination. Tests group cohesion under pressure.
- **The Order Holds (50+):** Full integration: live coordination + deviation-response + group cohesion + code-maintenance simultaneously.

### Feedback
- Effective live coordination → "The order moves as one. Each member in their role. The code lives in action."
- Enforcement response → "You corrected Aldric. The code was applied. But was this proportional? The group asks."
- Lone-wolf response → "You coordinated alone. The group was there. Was this a choice or an absence?"
- Performed sophistication → "You held space for all members. But did you coordinate? The order needs action, not frameworks."
- Group cohesion maintained → "The challenge came. The group held. The code was tested and found true."

### Difficulty Adaptation
- Group size: 2 companions → 3 companions → 4 companions
- Companion relational styles: simple → complex → conflicting
- Deviation frequency: rare → occasional → frequent
- Challenge complexity: simple → multi-step → multi-party

### Internal Progression
| Phase | Checkpoint range | What changes |
|---|---|---|
| The Shared Task | 1-5 | Simple live group-coordination |
| The Code in Action | 5-15 | Complex role-appropriate coordination |
| The Member's Deviation | 15-30 | Response to live relational deviation |
| The Group's Response | 30-50 | Group cohesion under pressure |
| The Order Holds | 50+ | Full live group-belonging integration |

## 4. Item Pool

- **Shared task scenarios:** Simple group coordination tasks — 20+
- **Code-in-action tasks:** Complex role-appropriate coordination — 20+
- **Member deviation scenarios:** Responses to live relational deviations — 20+
- **Group challenge scenarios:** Group cohesion under pressure — 15+
- **Code-maintenance scenarios:** Maintaining group code under adversity — 10+

## 5. Technical Requirements

- **Input types:** Tap (coordination action); hold (role confirmation); swipe (group navigation)
- **Timing:** Coordination response latency tracked; deviation-response time measured; group cohesion quality assessed
- **NPC/AI:** Companion relational-style simulation; deviation-event generation; group-dynamic modelling; shadow-signal accumulator; live coordination quality tracking
- **LLM:** Companion dialogue; deviation narration; group-challenge delivery; coordination quality assessment
- **State persistence:** Full group coordination history; companion interaction patterns; deviation-response quality; group cohesion tracking; cross-session group continuity; drive/shadow signal accumulation; checkpoint position
