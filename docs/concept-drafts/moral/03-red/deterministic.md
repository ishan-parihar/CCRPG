# Moral / Red — Deterministic Game Concept

> **Axis:** The deterministic axis probes moral intelligence through OBJECTIVE, MEASURABLE tasks — consequence-mapping accuracy, risk/reward calculation speed, punishment-detection precision. No ambiguity, no interpretation, no LLM subjectivity. Pure moral-cognitive capacity at Red: can you calculate what happens next?
>
> **Why this axis for Moral/Red:** At Red, morality IS consequence-logic. "Will I be punished? Will I be rewarded?" The deterministic axis strips away narrative, emotion, and social context to measure RAW consequence-calculation capacity. This provides ground truth for cross-modality validation.

---

## 1. Game Identity

- **Title:** "The Consequence-Reader"
- **Core mechanic:** The player observes action→consequence sequences and must predict, calculate, and optimise based on visible consequence-logic. No moral framing — pure "what happens if I do X?"
- **Duration:** 2-4 minutes per session (infinite checkpoints; fatigue-aware)
- **Internal progression:** The Obvious → The Delayed → The Chain → The Trade → The Calculation

---

## 2. Catalyst Delivery

**Catalyst:** Actions produce consequences. Some consequences are immediate; some are delayed. Some are visible; some are hidden. The game asks: "Can you SEE what happens next?" The contact boundary is: "Is your consequence-logic functional?"

**Unconscious response:**
- *Submergent:* Do they engage consequence-logic at all? Do they over-engage (exploitation)? Freeze (paralysis)? Bypass (perform without calculating)?
- *Emergent:* Can they hold longer consequence-chains? Calculate more complex trade-offs?

**Integration path:** Rewards ACCURATE consequence-prediction. Not "good" choices — ACCURATE predictions. The moral content is implicit: accurate consequence-logic is the FOUNDATION of all moral reasoning.

**Successful integration:** The player accurately predicts consequences across 2-step chains, calculates risk/reward ratios, and detects punishment/reward patterns.

---

## 3. Game Design

### Setup
The Consequence-Reader: a world of visible cause-and-effect. Actions produce results. The player watches, predicts, and acts. No moral language — just "what happens next?" The aesthetic: Red-stage arena where consequences are PHYSICAL and VISIBLE (push a boulder → it rolls → it hits something → that thing breaks).

### Interaction
- **The Obvious (1-5):** Action → immediate visible consequence. "Push this → that falls." Binary prediction.
- **The Delayed (5-15):** Action → delayed consequence. "Take this now → lose that later." 2-step chains.
- **The Chain (15-30):** Action → consequence → consequence. Multi-step cascades. "If I do X, then Y happens, then Z."
- **The Trade (30-50):** Competing consequences. "This action gives A but costs B. That action gives C but costs D. Which is better?"
- **The Calculation (50+):** Full consequence-mapping with uncertainty, delay, and trade-offs simultaneously.

### Feedback
- Accurate prediction → "You saw it coming. The consequence-reader's eye is sharp."
- Inaccurate → "That's not what happened. Watch again. What did you miss?"
- Exploitation-only → "You calculated for yourself. But there were other consequences you didn't map."
- Paralysis → "You froze. But look — nothing terrible happened. Choose next time."

### Difficulty Adaptation
- Chain length: 1-step → 2-step → 3-step
- Delay: immediate → short delay → long delay
- Visibility: fully visible → partially hidden → inferred
- Trade-off complexity: binary → multi-option → competing priorities

### Internal Progression
| Phase | Checkpoint range | What changes |
|---|---|---|
| The Obvious | 1-5 | 1-step, immediate, fully visible |
| The Delayed | 5-15 | 2-step, short delay, mostly visible |
| The Chain | 15-30 | Multi-step cascades; some hidden links |
| The Trade | 30-50 | Competing consequences; optimisation required |
| The Calculation | 50+ | Full complexity: chains + delays + trades + uncertainty |

---

## 4. Item Pool

### Item types
- **Consequence-chains:** Action→result sequences of varying length and complexity
- **Trade-off scenarios:** Competing consequences requiring optimisation
- **Delayed-consequence puzzles:** Actions with non-immediate results
- **Detection tasks:** "Which action caused this consequence?"
- **Prediction tasks:** "What will happen if X?"

### Minimum pool size
- 40+ 1-step, 30+ 2-step, 25+ multi-step, 20+ trade-offs, 15+ detection tasks

### Drive/shadow mapping
- Self-only optimisation → dark-addiction; frozen/incomplete → dark-allergy
- Confident but inaccurate → golden-addiction; accurate but disengaged → golden-allergy

---

## 5. Technical Requirements

### Input types
- Tap-to-select (choose predicted consequence); drag (arrange consequence-chains); binary choice (which trade-off)

### Timing requirements
- Response latency measured (diagnostic for paralysis vs. engagement); no millisecond precision needed; generous windows (2-5 seconds per prediction)

### NPC/AI requirements
- None required. All consequence-chains are pre-defined environmental sequences.

### LLM requirements
- **Low:** Contextual framing and feedback narration only. All scoring is algorithmic.

### State persistence
- Prediction accuracy per chain-length; trade-off optimisation quality; latency patterns; self-only vs. comprehensive mapping ratio; engagement patterns; drive/shadow signals; fatigue state; checkpoint position
