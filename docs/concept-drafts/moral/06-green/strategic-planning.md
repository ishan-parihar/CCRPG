# Moral / Green — Strategic-Planning Game Concept

> **Axis:** Planning the moral life — structuring ethical commitments across competing contexts and timeframes.  **Why this axis for this module:** Green moral capacity must extend beyond momentary judgement into sustained ethical architecture; planning reveals whether contextual ethics can be lived coherently over time.

---

## 1. Game Identity

**Name:** The Ethical Architect
**Core loop:** Player designs and maintains a "moral ecology" — allocating ethical attention, commitment, and care across competing life-domains over simulated time. Planning decisions reveal whether contextual sensitivity enables or paralyses sustained moral action.
**Session length:** 6–10 minutes (1 planning cycle per session).
**Infinite checkpoint:** Save at any planning-phase boundary; resume mid-cycle.

## 2. Catalyst Delivery

**Catalyst frequency:** Green moral — sustained contextual ethical commitment.
**Shadow provocation:** DA surfaces as inability to prioritise — all moral claims receive equal (minimal) allocation, no domain gets genuine commitment. DAll surfaces as rigid allocation — same moral priorities regardless of shifting context. GA surfaces as over-architectured plans that reference developmental stages but lack concrete care-commitments. GAll surfaces as refusal to rank moral domains even when resource-scarcity demands it.
**Drive probing:** Eros — planning that reaches toward new moral territory. Agape — planning that returns to neglected care-relationships. Agency — planning that commits resources decisively. Communion — planning that integrates others' moral needs.
**Integration path:** Diagnosis (baseline planning patterns) → Healing (planning challenges that make shadow-patterns costly) → Evolution (planning that requires simultaneous care-justice-context integration across time).

## 3. Game Design

**Mechanic:** Player manages a moral-ecology board with 6–8 life-domains (family, community, profession, self, ecology, strangers, institutions, growth). Each turn represents a time-period. Player allocates limited "moral energy" tokens across domains. Contextual events shift domain-urgency each turn. Consequences accumulate — neglected domains degrade; over-invested domains show diminishing returns.
**Adaptive difficulty:** Early cycles have clear urgency signals; later cycles introduce: (a) competing urgent claims, (b) long-term vs. short-term tension, (c) cultural context shifts that reframe priorities, (d) moral-framework conflicts between domains.
**Planning constraints:** Limited tokens force genuine prioritisation. "Equal distribution" is mechanically suboptimal (spread too thin = all domains degrade). But rigid allocation ignores context (events punish inflexibility).
**Shadow confrontation:** After 5+ cycles, system presents a "moral audit" — showing the player's allocation patterns over time, making shadow-structures visible through data.

## 4. Item Pool

**Pool structure:** 100+ contextual events that shift domain-urgency. Events tagged with: affected domain, care-justice orientation, contextual complexity, shadow-provocation target.
**Event types:** (a) Urgent care-claims — someone needs you NOW. (b) Systemic justice-demands — institutional change requires sustained investment. (c) Context-shifts — cultural/life changes that reframe what matters. (d) Ranking provocations — events that reward explicit moral prioritisation.
**Domain dynamics:** Each domain has a health curve, decay rate, and relational connections to other domains. Neglect cascades. Over-investment plateaus.
**Cycle length:** 8–12 turns per planning cycle. Each turn = one allocation decision + one contextual event.

## 5. Technical Requirements

**Input:** Drag-allocation of tokens onto domain nodes. Tap to view domain status. Minimum 44px touch targets.
**Timing:** No per-turn time limit (deliberation valid). Total cycle-time recorded. Optional soft time-pressure in advanced cycles.
**Telemetry:** Per-turn allocation vectors, response to contextual events (shift magnitude), domain-health trajectories, planning consistency vs. flexibility ratio, shadow-flag activations.
**Adaptive engine:** Allocation-pattern analysis across 3+ cycles detects shadow orientation. Event selection targets detected shadow with increasing consequence-severity. Moral-audit presentation adapts to shadow type.
**Accessibility:** Token allocation via keyboard/switch input; domain status available as text; colour-blind safe domain indicators; screen-reader compatible board state.
