# R&D Roadmap — Concept-Draft Development

> **Scope:** 512 concept-draft documents (64 modules × 8 files each)
> **Goal:** First-principles game designs for every assessment game in the CCRPG ecosystem
> **Approach:** Phase-gated, Red-stage-first, with each phase producing playable/testable modules

---

## 1. Trajectory Alignment Based on Latest Understanding

### 1.1 Key insights from foundations/13 (Architecture of Consciousness)

The integration of the emergent/submergent shadow model changes our development trajectory:

| Previous assumption | Updated understanding | Impact on concept-drafts |
|---|---|---|
| Shadows are binary (addiction/allergy) | Shadows are 4-quadrant (dark-addiction, dark-allergy, golden-addiction, golden-allergy) | Each module's shadow-diagnostics file must address all 4 quadrants |
| Games assess capacity only | Games must assess capacity AND drive-health AND shadow-state simultaneously | Every game concept must specify how it implicitly measures drives and surfaces shadows |
| Advancement is linear (pass stage → next stage) | Advancement requires both heal/evolve (bottom-up) AND evolve/heal (top-down) | Games must support both vectors — some games heal, some games evolve, some do both |
| The player "moves through" stages | The player always remains within the holon — earlier stages are always accessible and must remain healthy | Games at earlier stages are never "outgrown" — they become shadow-mode encounters |
| Assessment is separate from gameplay | Assessment IS gameplay; the game IS the developmental catalyst | No concept-draft should feel like a "test" — every game must be intrinsically engaging |

### 1.2 Trajectory deviations

Based on these insights, the following deviations from the original plan are proposed:

1. **Each concept-draft must specify BOTH capacity-mode and shadow-mode** — not just "what does this game measure" but "how does this game heal/evolve"
2. **Golden-shadow games are a new category** — games specifically designed to surface the terror of transcendence and invite the player toward their next stage
3. **The Atman Project defenses must be addressed per-module** — each module's shadow-diagnostics must specify which defenses are most active at that stage and how the game circumvents them
4. **The contact boundary mechanic** — games should be designed to work WITH the player's selective permeability, not against it. The game presents catalyst that the player's unconscious is already seeking.

## 3. Per-Module R&D Process

For each of the 64 modules, the R&D process is:

### Step 1: Shadow-Diagnostics First (1 day)

Before designing any games, define the module's shadow landscape:
1. Name the 4 shadow archetypes (dark-addiction, dark-allergy, golden-addiction, golden-allergy)
2. Define what healthy drive expression looks like at this (line, stage)
3. Define what pathological drive expression looks like
4. Identify which Atman Project defenses are most active
5. Specify the heal/evolve and evolve/heal vectors

This grounds all subsequent game design in the developmental reality of the module.

### Step 2: Deterministic Game (half day)

The most concrete, objectively scoreable game. Establishes the capacity ceiling.
- What is the cognitive/motor/perceptual task?
- What difficulty parameter adapts?
- What is the item pool?

### Step 3: Language-Reflective Game (half day)

The deepest, most qualitative game. Requires LLM rubric design.
- What prompt surfaces the developmental structure?
- What does a Red-stage response look like vs. an Amber-stage response?
- What is the LLM scoring rubric?

### Step 4: Scenario-Choice Game (half day)

The choice-pattern game. Reveals values and decision structures.
- What scenarios are developmentally diagnostic?
- How are options tagged to stages?
- How does the choice pattern reveal shadow state?

### Step 5: Embodied Game (half day)

The body-based game. Grounds assessment in physical reality.
- What physical input is required?
- How does timing/rhythm/endurance reveal this capacity?
- How does the body reveal drive-health?

### Step 6: Strategic Game (half day)

The planning/resource game. Reveals executive function and foresight.
- What multi-step problem is appropriate for this stage?
- How does strategic allocation reveal willpower/agency?

### Step 7: Social/Cooperative Game (half day)

The relational game. Reveals interpersonal capacity and communion.
- What NPC interaction is appropriate?
- How does coordination reveal attunement?
- How does the social context reveal drive-health?

### Step 8: Immersive RPG Game (half day)

The ecological validator. Assessment is invisible.
- How does this module manifest in free-play?
- What combat/exploration/dialogue mechanics embed this assessment?
- How does spontaneous behaviour reveal the player's true stage?

## 4. Quality Criteria for Concept-Drafts

Each concept-draft is considered complete when it answers:

| Criterion | Question |
|---|---|
| **Developmental validity** | Does this game genuinely measure the capacity it claims to? |
| **Shadow sensitivity** | Can this game detect all 4 shadow quadrants? |
| **Drive implicitness** | Does this game measure drives WITHOUT the player knowing? |
| **Engagement** | Would a player WANT to play this, independent of assessment? |
| **Anti-gaming** | Can this game be spoofed? If so, how do other modalities cross-validate? |
| **Scalability** | Can the item pool be expanded to 100+ items without redesign? |
| **Heal/evolve support** | Does this game catalyse genuine development, not just measure it? |
| **Age-adaptivity** | Can this game be presented to a 7-year-old AND a 40-year-old? |

## 5. Cross-Module Patterns to Research

During concept-draft development, the following cross-cutting research questions must be addressed:

### 5.1 The "same game, different stage" problem

Many game TYPES appear at multiple stages (e.g., n-back appears at Magenta through White). The concept-draft must specify what makes the Red-stage version qualitatively different from the Amber-stage version — not just "harder parameters" but different cognitive structures being engaged.

### 5.2 The golden-shadow game design challenge

How do you design a game that surfaces the terror of transcendence? This is the hardest design challenge in the system. The game must:
- Present the NEXT stage's capacity as an option (not a requirement)
- Make the option genuinely attractive (not forced)
- Observe whether the player approaches or avoids
- Score the QUALITY of approach (genuine engagement vs. performative)

### 5.3 The heal/evolve integration

Each module needs games that work in BOTH directions:
- **Heal games:** Present the current stage's capacity and observe drive-health (are they clinging? avoiding?)
- **Evolve games:** Present the next stage's capacity and observe willingness + quality of engagement

### 5.4 The compound shadow problem

Some shadows reinforce each other across modules. For example:
- Cognitive/Red/dark-addiction + Emotional/Red/dark-allergy = "thinks instead of feeling"
- Willpower/Amber/dark-addiction + Spiritual/Amber/golden-allergy = "rigid discipline blocking spiritual growth"

The shadow-diagnostics files must map these cross-module relationships.

## 7. Success Metrics

The concept-draft phase is complete when:

1. All 512 files exist with substantive content (not stubs)
2. Each module's 7 games cover ≥ 3 modalities with genuine variety
3. Each module's shadow-diagnostics addresses all 4 quadrants
4. Cross-module relationships are mapped for at least the Red-Amber-Orange tier
5. LLM rubrics are written for all language-based games
6. At least 3 games per module have been prototyped and playtested
7. The concept-drafts are sufficient for any developer to implement without further design input
